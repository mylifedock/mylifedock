2. Product Philosophy & Core Objectives

2.1 The Sovereign Data Problem

Modern individuals must manage and safeguard highly sensitive life records: Government Identity cards (Aadhaar, Passport, PAN), doctor prescriptions, diagnostic lab blood reports, product warranty invoices, and digital credentials. Conventional cloud services (Google Drive, Dropbox, 1Password, Bitwarden) rely on centralized company databases where third-party servers hold master decryption metadata, making user records vulnerable to corporate surveillance, commercial profiling, AI model training, and catastrophic cloud breaches.

2.2 The Sovereign Vault Solution

Personal Vault operates on the principle of Zero-Knowledge by Construction:

  • Zero Developer Servers: Personal Vault runs 100% locally on the user's client device. Zero server APIs, zero analytics cookies, zero tracking pixels.
  • Client-Side Cryptography: All encryption, decryption, and key derivation take place strictly inside the user's device memory using WebCrypto and native OS Hardware Enclaves.
  • Absolute User Sovereignty: Even under subpoena, developers cannot decrypt or produce user data because no user data ever reaches the developers.

5. Step-by-Step User Operations Handbook

User Journey 1: Initial Vault Setup & Recovery Key Safeguarding
  1. Open Personal Vault on your device.
  2. Enter your Display Name (e.g. B.S.S. Dinesh) and check the Terms & Privacy Policy checkbox.
  3. Review the 3 Core Pillars slideshow and click Continue.
  4. Set a strong Master Passphrase (minimum 8 characters) and confirm it.
  5. Critical Step: The app displays your 256-bit Hex Recovery Key (XXXX-XXXX-XXXX-...). Click Copy Recovery Key and store it offline.
  6. Check the confirmation box: "I have safely stored my recovery key" and click Enter Personal Vault.
User Journey 2: Adding a Prescription for a Child
  1. Tap Medical & Health Records → Click + Add Prescription.
  2. In the Patient dropdown, select your child (e.g. 👶 Aarav Sharma).
  3. Enter the Doctor Name, Hospital, Department, and Diagnosis.
  4. Set the Prescription Date and upcoming Follow-up Date.
  5. Attach prescription scans or use Snap & Auto-Fill to extract text via OCR.
  6. Click Save Prescription.
User Journey 3: Upgrading to Pro & Activating License
  1. Upon saving 10 items, the Pro Upgrade Modal opens (or go to Settings → Activate Pro License).
  2. Click Get Pro License to pay via Razorpay (https://razorpay.me/@bssdinesh).
  3. Check your email for your unique license key (MLD-PRO-eyJuYW1l...).
  4. Paste the key into the activation modal and click Activate Pro License.
User Journey 4: Exporting Encrypted Backups (.mldv)
  1. Go to Settings → Backup & Export.
  2. Click Export Encrypted Backup (.mldv).
  3. Save the encrypted file to your internal storage, USB drive, or private storage.
User Journey 6: Submitting Direct Feedback & Feature Requests
  1. Click 💬 Send Feedback in the Sidebar navigation or navigate to Settings → Share Feedback.
  2. Select your Category: Feature Request (💡), Bug Report (🐞), General Review (⭐), or Question (❓).
  3. Choose your 1 to 5 Star Rating.
  4. Enter a brief Topic / Summary and your detailed comments.
  5. Click 🚀 Send to Founder to open your email client pre-filled with the tagged subject line [MyLifeDock Feedback] <Category>: <Topic> directed to mylifedock@gmail.com.

Admin Task 2: Setting up Free Automated License Mailer
  1. Open Google Apps Script (https://script.google.com) → New Project.
  2. Paste the code from app/scripts/razorpay-auto-mailer.gs.
  3. Deploy as Web app (Access: Anyone) → Copy Webhook URL.
  4. In Razorpay Dashboard → Settings → Webhooks: Add URL with events payment.captured and order.paid.
Admin Task 3: Building Signed Android App Bundle (.aab)
  1. Generate Keystore: keytool -genkey -v -keystore personal-vault-release.keystore -alias personalvault -keyalg RSA -keysize 2048 -validity 10000.
  2. In Android Studio: Build → Generate Signed Bundle / APK → Android App Bundle.
  3. Upload the generated .aab file to Google Play Console.

7. Technical Specifications & Data Dictionary (Annexures)

Annexure A: Cryptographic Engine Specifications

  • Key Derivation: PBKDF2-HMAC-SHA256 (100,000 rounds, 128-bit random salt).
  • Payload Cipher: AES-256-GCM with 96-bit unique IV and 128-bit authentication tag.
  • Key Wrapping: AES-KW (NIST SP 800-38F).
  • Offline Licensing: HMAC-SHA256 over base64 JSON payload.
